# Third-party licensing

`sdl-dos-ports` follows the model doskutsu established: **open engine +
locally-authored patches, no redistributed proprietary assets.**

## What this repository contains

`shared/` vendors nothing directly — it carries a **local patch series**
against upstream sources that individual port repos also pin (currently the
SDL3 DOS backend, `libsdl-org/SDL`, zlib-licensed). A port repo applies
these patches to its own pinned checkout of the vendor source; this repo
never ships a full copy of SDL, SDL_mixer, or SDL_image.

| `shared/patches/sdl3-dos/*` | zlib (inherits SDL's license) | patches against `libsdl-org/SDL`'s DOS backend |
| `shared/patches/sdl3-mixer/*` | zlib (inherits SDL_mixer's license) | |

## `shared/audio/opl3_sink.{c,h}` -- why this is recorded as MIT, not GPLv3

`opl3_sink.{c,h}` reimplements the GM-program-to-OPL3-register mapping,
voice allocator, and register math that doskutsu's own
`patches/nxengine-evo/0103` (plus fixes `0106`/`0141`/`0142`/`0171`/`0232`)
authored against NXEngine-evo, a GPLv3 project -- doskutsu's own
`THIRD-PARTY.md` records those patches as GPLv3 derivatives. This repo's
`shared/` is MIT.

The same tension already existed for `shared/audio/midi_sched.{c,h}`
(a plain-C rewrite of doskutsu's `MidiScheduler.cpp`, also GPLv3-derivative
in its origin repo), recorded above as "MIT, original work, this repo, no
upstream dependency." The operator made an explicit decision (2026-09-12)
to extend that same treatment to `opl3_sink`: a rewrite from C++ to C,
restructured onto the `midi_sched_sink` interface and verified behaviorally
equivalent rather than textually copied, is judged a new independent work
rather than a derivative of the original source text. This module drops
every doskutsu-specific dependency (`MidiBackend`/`Logger.h`/
`ResourceManager`) and every doskutsu-specific behavior added by later
patches not in the list above -- notably the per-drum-note envelope table
from doskutsu's own later patches `0298`/`0307`, which is tuned to that
project's own Organya-to-MIDI drum mapping and would fail this hub's
"nothing game-specific" rule on its own regardless of licensing; this
sink uses one generic drum patch for the whole percussion channel,
matching the original, more generic `0103` shape.

Recorded here for the same reason the licensing rules in this file exist at
all: so this judgment call is visible and re-examinable, not silently
assumed. If this reasoning is ever revisited, both `midi_sched.{c,h}` and
`opl3_sink.{c,h}` should be reconsidered together, since they rest on the
same argument.

`shared/audio/waveblaster_sink.{c,h}` (S5, WaveBlaster hoist) rests on the
exact same argument again: a plain-C rebase of doskutsu's
`MidiBackendWaveBlaster` (`patches/nxengine-evo/0102` against NXEngine-evo,
GPLv3-derivative in its origin repo) onto `midi_sched_sink`, dropping every
doskutsu-specific dependency (`MidiBackend`/`Logger.h`) the same way
`opl3_sink` did. Applying the operator's 2026-09-12 decision to this module
too, without a separate re-ask, is a judgment call by whoever lands this --
flagged here explicitly so it is visible and can be confirmed or reversed
rather than silently assumed to carry forward.

## `shared/audio/opl3bank.dat` -- DMXOPL provenance, independently verified

The bank is generated by `gen-opl3-bank.py` from DMXOPL's `GENMIDI.op2`
(github.com/sneakernets/DMXOPL). doskutsu's own `THIRD-PARTY.md` recorded
this as MIT while a DoomWiki page for the same project separately lists
CC BY-SA 4.0 -- per this hub's own "never guess a license" rule
(`docs/licensing.md`), that disagreement was resolved by reading the actual
upstream LICENSE file directly, not by trusting either secondhand claim:

- Pinned commit: `e83c144a2e6d3c283e20f9d16d011126931892f5` (tip of the
  `DMXOPL3` branch, last pushed 2018-07-13). doskutsu itself never recorded
  an exact DMXOPL commit anywhere; this pin was established for the first
  time during this hoist (2026-09-12), verified stable because
  `GENMIDI.op2`'s own last change (2018-01-02) predates it.
- `LICENSE` at that commit, fetched and read directly: plain, unmodified
  MIT License text. This settles the doskutsu-vs-DoomWiki disagreement in
  favor of MIT from the primary source.
- `GENMIDI.op2` at that same commit: sha256
  `92fc03c7734c45b1ece2bfad1f79d1abbd2b27ec6b45fbfb1c5a74f5ce0138c9`.
  Running it through this repo's own (unmodified from doskutsu's)
  `gen-opl3-bank.py` reproduces `opl3bank.dat` byte-for-byte (sha256
  `8c7a17a017a213f5f4c63a631fa2eb06b33640b1c49e5e3faf0eb203d25a354b`),
  confirming both the pin and that the generator is genuinely reproducible.

## What a port repo must track separately

Every port repo is responsible for its own `LICENSE-REVIEW.md` (see
`templates/LICENSE-REVIEW.md`) covering:

- the game engine's own source license (e.g. GPLv3 for NXEngine-evo),
- any DOS-specific patches authored against that engine,
- game asset licensing and redistribution rights (music, fonts, sprites),
- whether the finished port binary can be distributed at all, and under
  what conditions (open engine + user-supplied original data is the
  fallback model whenever asset licensing is uncertain).

This repository, its `shared/` layer, and `gallery/` must never contain
commercial or copyrighted game data, proprietary fonts, or music requiring
separate permission — screenshots of a port's UI in `gallery/` are fine;
game data files are not.
