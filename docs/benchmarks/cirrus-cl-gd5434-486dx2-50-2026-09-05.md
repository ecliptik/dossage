## Results
Average FPS: **14.966555** (4475 frames / 299s, `Game time = 4:59`,
  captured verbatim from `FPS.TXT`). **PASS** against the 486DX2-50 KPI
  line (14.90fps) with real margin -- comfortably clear, not a
  borderline result. Frame-time samples: "4474 used, 0 rejected
  non-positive, 0 rejected below 0.001s, 0 rejected above 5.0s" -- clean.

  **Same 299s/4475-frame/14.966555fps shape as the 486DX2-66+Cirrus
  leg, exactly.** This is the important result: going in, the concern
  was that the small banked-path cost found at 486DX2-66 might be
  *larger* at 486DX2-50's tighter margin, possibly threatening the KPI.
  It is not larger -- it is identical, down to the fps figure, at both
  CPU tiers. That CPU-tier-independence is itself informative (see
  Notes): a cost that scaled with CPU cycles would be expected to cost
  *more* wall-clock time on the slower chip, not the same amount.
1% low: RUNMANIFEST `fps_p50=15.00`, `fps_p95=14.79` -- matches the
  established ViRGE+486DX2-50 figure (`14.80`) almost exactly. No
  additional percentile-level degradation from the banked path at this
  tier beyond what the average-fps effect already captures. Zero
  `critical_count`/`warn_count`, zero rejected samples -- none of the
  original pre-fix pacer-timing or audio-tier signatures (the
  ~9-10fps high-tier collapse, the `fps_p50=16.67`/`fps_p95=9.09`
  artifact) reappeared.
Simulation rate: pacer-bound at the 15fps design ceiling -- confirms
  the Round 1-3 fix-validation arc's result (established on Mach64)
  holds on Cirrus's banked path too, not just LFB.
Audio underruns: not instrumented. `AUDIO_PRESENT` confirmed multiple
  times mid-run. Tier-matched build, no pitch/tempo mismatch to caveat.
Peak memory: not measured.
Notes:
- **KPI now confirmed on all three cards at the port's own
  minimum-target CPU tier.** Mach64 (Round 3, 14.992fps mean),
  ViRGE (486DX2-50 leg, 15.016779fps), and now Cirrus (14.966555fps) --
  the pacer-timing and audio-tier fixes hold across every video path
  this port supports at its own `dos_minimum_target` hardware, not just
  the CPU/card pairing the fix-validation arc was originally developed
  against.
- **The banked-path cost is CPU-tier-independent in magnitude, which
  argues against a pure CPU-cycle-cost mechanism** -- consistent with
  (though a smaller-scale echo of) this campaign's earlier finding that
  the pacer's own bimodal timing clusters are driven by a fixed-
  frequency hardware tick, not CPU clock speed
  (`docs/PACER-TIMING-INVESTIGATION.md`). If the banked multi-bank
  walk's extra cost were N extra CPU cycles per frame, a slower CPU
  (486DX2-50) should take longer in wall-clock terms to execute those
  same N cycles than a faster one (486DX2-66), making the effect
  *larger* on the slower chip -- not identical. That it is identical
  here suggests the cost might instead be a small number of extra I/O
  waits (e.g. VGA bank-select port writes with a fixed hardware
  settling time) rather than pure instruction-execution overhead --
  plausible, not confirmed; would need dedicated instrumentation
  (a per-stage diagnostic build, same approach as the 486DX2-50 Phase 2
  campaign) to root-cause properly. Not pursued further here since it
  doesn't threaten the KPI at either tier -- flagging as a candidate
  follow-up if this port ever wants the banked path's per-frame cost
  characterized precisely, not as an open action item.
- Visual: matched `docs/screenshots/dossage-gameplay.png`, no
  corruption. Clean two-Escape exit confirmed via the hardware camera.
- `SDLDBG.LOG`: identical shape to every Cirrus leg --
  `DOSVESA-CTRL: VBE 3.0 total_vram=1024_KB`, `oem_string='Universal
  VESA VBE 6.70'`; `cirrus-lfb-aperture-bug: detected -> forcing banked
  path`; `DOSVESA-MODESET: id=0x01D9 320x240 16bpp has_lfb=1 use_lfb=0
  banked=1`.
- Wall-clock bracket (control-host UTC): launch 1788626580.27, title

  largest launch/warmup overhead of any leg this campaign, consistent
  with this being the slowest CPU tier measured; not clock loss, same
  documented pattern as every other leg).
