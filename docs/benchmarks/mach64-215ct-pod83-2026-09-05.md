## Results
Average FPS: **15.016779** (4475 frames / 298s, `Game time = 4:58`,
  captured verbatim from `FPS.TXT`). **PASS.** Frame-time samples:
  "4474 used, 0 rejected any category" -- clean.

  **Lands on the campaign's usual 298s/15.016779fps signature, not the
  "one second over" shape.** This is genuinely informative given
  Mach64+Am5x86-133 (`docs/benchmarks/mach64-215ct-am5x86-2026-09-05.md`)
  showed the opposite result at a *slower* CPU tier on the identical
  card and build: POD83 is faster than Am5x86-133, so if the effect
  scaled with raw CPU speed alone this is the expected direction, but
  the same `fps_p95` (`14.96`) as the Am5x86-133+Mach64 leg that DID
  land at 299s shows the underlying percentile distribution is
  essentially identical between the two runs -- only the specific
  integer-second rounding outcome differs. Consistent with (not proof
  of) the boundary-adjacent-jitter reading raised in the
  Am5x86-133+Mach64 writeup: a true frame period sitting close enough
  to the 298/299s reporting threshold that individual lives can land on
  either side, rather than a value fixed by CPU tier or card. Reported
  as measured, not adjusted toward either interpretation.
1% low: RUNMANIFEST `fps_p50=15.00`, `fps_p95=14.96` -- identical to
  the Am5x86-133+Mach64 leg's percentiles despite the different
  reported average, reinforcing that this is the same underlying
  regime with a different rounding outcome, not a different regime.
  Zero `critical_count`/`warn_count`.
Simulation rate: pacer-bound at the 15fps design ceiling, comfortably.
Audio underruns: not instrumented. `AUDIO_PRESENT` confirmed multiple
  times mid-run. Tier-matched build, no pitch/tempo mismatch to caveat.
