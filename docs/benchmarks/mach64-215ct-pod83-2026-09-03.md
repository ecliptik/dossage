# Benchmark

## Hardware
CPU: Intel Pentium OverDrive (P24T), ~83MHz. **Identity RESOLVED
  2026-09-03 -- three independent confirmations, not software-only.**
  `dinspect`'s live scan initially read `CPU: AMD Am5x86` for this chip;
  the operator directly confirmed the physical swap (only CPU installed,
  BIOS detected it correctly at POST), and `dinspect` ruled out its own
  vendor-string logic being at fault -- creating a genuine, real
  mystery, not a simple misdetection. Root cause: **two real, distinct
  bugs**, found by tracing rather than guessed. (1) An unbounded
  TSC-calibration loop hung on this rig's first-ever Pentium-class chip;
  the daemon's own blind reboot cadence killed the hang before a fresh
  report was written, so the "live" scan actually read a stale,
  leftover Am5x86-era file without either side realizing it was stale.
  (2) Once the loop was bounded, `RDTSC` itself turned out to fault
  outright under EMM386 on this specific OverDrive part -- fixed by
  `dinspect` detecting the V86 monitor and falling back to a PIT-timed
  speed estimate. **Confirmed correct three independent ways**: the
  fixed `dinspect.exe` now reports `CPU: Intel Pentium OverDrive / CPU
  Speed: ~83 MHz / CPU Features: FPU TSC MSR CX8`; an independent raw
  CPUID leaf 0/1 dump (`CPUIDDM2.COM`, no dinspect code involved)
  matches exactly; and PhoenixBIOS 4.04's own POST text, captured via
  the rig's independent hardware camera (outside DOS entirely), reads
  "CPU = Pentium 80 MHz" -- genuinely Pentium-class by three unrelated
  measurement paths. **Neither side was simply wrong**: the physical
  hardware really was correct all along (as the operator said), and
  `dinspect` really did have two real bugs (as its own investigation
  suspected) -- both true simultaneously, which is why chasing this
  down properly mattered instead of accepting either claim alone.

## Results
Average FPS: **14.966555** (4475 frames / 299s) -- essentially at the
  design ceiling, in the same band as the Am5x86-133 result (15.02fps)
  and clearly faster than either Intel 486DX2 tier. **No established
  reference for this CPU/build/card combination** (the only prior POD83
  data predates all pacer/audio work, not comparable) -- first datum,
  not a pass/fail.
1% low: RUNMANIFEST `fps_p50=16.67`, `fps_p95=9.09` -- **the known
  pre-fix artifact, not a new finding.** This leg used the unfixed build
  deliberately (see Build above); these values are exactly what every
  other build-`f1f867ccadad` run reports (see
  `docs/PACER-TIMING-INVESTIGATION.md`) and should be read the same way
  -- not descriptive of this CPU's real per-frame distribution, an
  artifact of `gettimeofday()`'s DOS-tick granularity.
Simulation rate: locked at 15fps target; this CPU has real pacer slack,
  same regime as 486DX2-66 and Am5x86-133.
Audio underruns: not instrumented. Two `vcctrl_audio_verdict` checks
  (~35s, ~185s), both `AUDIO_PRESENT`, music-like. **Known audio-tier
  mismatch bug applies to this run too** -- `AUDIO_PRESENT` confirms
  presence only, not correct pitch/tempo (see any other benchmark file
  this campaign for the full mechanism; fix in progress, separate from
  this leg).
Peak memory: not measured.
Notes:
- **CPU identity RESOLVED** -- see Hardware section above for the full
  three-way confirmation (fixed dinspect, independent CPUID dump, BIOS
  POST text). No longer resting on operator testimony alone.
- **Rig hazard found along the way, worth knowing for any future probe
  work on this rig**: executing `RDTSC` hard-wedges this specific
  machine under EMM386 on any boot profile -- needs a full power cycle
  to recover, not just a keyboard-level reboot. This also explains an
  earlier unrelated hang (HWiNFO) during this same investigation.
  `docs/PACER-TIMING-INVESTIGATION.md`'s recommended follow-up probe
  work does not currently use RDTSC, but if any future timing probe on
  this rig is tempted to (e.g. for a finer-grained clock than `uclock()`
  offers), test that on a CPU/profile known to tolerate it first, or
  expect a hard hang requiring physical recovery.
- **Second life note**: Q did not register as an exit keystroke after
